# Contributing to Tuti Lab

Thank you for considering a contribution. Focused, evidence-based contributions are easiest to review.

## Before contributing
1. Read [VISION.md](VISION.md) and [ARCHITECTURE.md](ARCHITECTURE.md).
2. Search existing Issues and Discussions.
3. Use synthetic examples and remove private or identifying information.
4. Describe the problem before proposing a solution.

## Issues and proposals
Include context, expected behavior, observed behavior, evidence (a minimal reproducible example or sanitized log), constraints, and unresolved questions.

## Pull Requests
- Keep each PR focused on one purpose.
- Explain the motivation and summarize changes.
- Update documentation where appropriate.
- Include tests for behavior changes when feasible.
- Identify assumptions and known limitations.
- Do not include secrets, private data, or code copied from private repositories.

## Review and approval
Public contributions are proposals until reviewed. A change merged here does not authorize changes to private repositories or production deployments. Production changes require separate authorization and review by the project owner.

## Communication and privacy
Portuguese and English are welcome. Be respectful, curious, and specific. Never post real guest records, phone numbers, booking references, account identifiers, private messages, credentials, or confidential infrastructure details. Use fictional data.
