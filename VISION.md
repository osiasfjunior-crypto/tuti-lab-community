# Tuti Lab — Vision and Principles

## Purpose
Tuti Lab is a collaborative space to investigate and develop an intelligent assistant shaped by real hospitality needs. The goal is not a generic chatbot at any cost. It is an assistant that knows its operational boundaries, organizes useful knowledge, and helps people complete work with less friction.

## The problem
A useful hospitality assistant must do more than produce fluent text. It must distinguish facts from guesses, respect the scope of each property and interaction, retrieve the right information, and make uncertainty visible.

A reliable memory system should:
- record information consistently;
- classify it without losing its meaning;
- retrieve it using all required conditions;
- connect related events and corrections;
- trace facts to their sources;
- keep information within the correct access scope.

## Product principles
1. **Honesty about uncertainty:** Tuti should say when it does not know or cannot verify something.
2. **Memory with provenance:** important facts should retain a reference to their source whenever feasible.
3. **Clear boundaries:** property, guest, project, and conversation contexts must not be mixed accidentally.
4. **Incremental development:** build and validate one capability at a time.
5. **Preservation:** do not replace existing components without evidence and approval.
6. **Human oversight:** consequential changes require review by an authorized person.
7. **Usability:** prefer simple, legible experiences over operational clutter.
8. **Privacy and security:** public collaboration must use synthetic or sanitized examples.

## Current research focus: memory reliability
We are investigating the gap between finding potentially relevant records and selecting only records that satisfy every mandatory condition in a query.

Questions include:
- How should a natural-language question become explicit retrieval criteria?
- How should mandatory attributes be combined?
- How should time and scope constraints be enforced?
- How should corrections and superseded facts be represented?
- How should insufficient evidence be reported?
- How can a result be traced to its source?

These are research questions, not claims that a final architecture has been chosen.
